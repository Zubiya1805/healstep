# Healio Database Architecture

This document outlines the PostgreSQL database schema for the Healio (recover-right) application. The database is designed to securely manage patient data, link medical reports to actionable recovery plans, and track daily progress.

## Tables

### 1. `users`
Stores user authentication and primary demographic/medical profiles.
- **id**: `SERIAL PRIMARY KEY` — Unique identifier for the user.
- **name**: `VARCHAR(255)` — Patient's full name.
- **email**: `VARCHAR(255) UNIQUE` — Patient's email (used for login).
- **password**: `VARCHAR(255)` — Bcrypt-hashed password.
- **gender**: `VARCHAR(20)` — Patient's gender.
- **disease**: `VARCHAR(255)` — Diagnosed condition or disease.
- **treatment_type**: `VARCHAR(255)` — The type of treatment or surgery undergone.
- **admission_date**: `DATE` — The date the patient was admitted.
- **created_at**: `TIMESTAMP DEFAULT NOW()` — Account creation date.

### 2. `reports`
Logs medical reports uploaded by the user, storing the file reference and the AI's plain-English extraction.
- **id**: `SERIAL PRIMARY KEY` — Unique identifier for the report.
- **user_id**: `INT REFERENCES users(id)` — Links the report to the specific patient.
- **file_path**: `VARCHAR(255)` — The local file path (handled via Multer) where the image/PDF is stored.
- **upload_date**: `TIMESTAMP DEFAULT NOW()` — When the report was uploaded.
- **extracted_summary**: `TEXT` — The simple English summary and findings generated by the AI.

### 3. `recovery_plans`
Stores the daily diet and exercise plans generated by the AI based on the user's latest report.
- **id**: `SERIAL PRIMARY KEY` — Unique identifier for the plan.
- **user_id**: `INT REFERENCES users(id)` — Links the plan to the patient.
- **report_id**: `INT REFERENCES reports(id)` — Links the plan to the specific report it was derived from.
- **plan_date**: `DATE` — The date this specific plan is intended for.
- **meal_plan**: `JSONB` — Structured JSON array of dietary recommendations.
- **exercise_plan**: `JSONB` — Structured JSON data holding the recommended physical activities and precautions.
- **created_at**: `TIMESTAMP DEFAULT NOW()` — When the plan was generated.

### 4. `daily_progress`
Records the patient's daily checklist submissions, used to compute their Recovery Score.
- **id**: `SERIAL PRIMARY KEY` — Unique identifier for the progress log.
- **user_id**: `INT REFERENCES users(id)` — Links the log to the patient.
- **date**: `DATE DEFAULT CURRENT_DATE` — The date the feedback was submitted.
- **completed_diet_items**: `JSONB` — Array of diet items the patient successfully completed.
- **completed_exercise_items**: `JSONB` — Array of exercise/precaution items the patient successfully completed.
- **health_status**: `VARCHAR(255)` — How the patient reported feeling (e.g., "Feeling great, no pain").
- **created_at**: `TIMESTAMP DEFAULT NOW()` — When the feedback was submitted.

## Relationships
- **One-to-Many (Users → Reports, Plans, Progress)**: The `user_id` is the foundational foreign key across all tables. When a user uploads a new report, a new row is created in `reports` linked to them.
- **One-to-Many (Reports → Plans)**: A `recovery_plans` row is linked to a specific `report_id`, allowing the system to track which medical document generated which specific set of advice.
- **Analytics Aggregation**: The dashboard calculates the Recovery Score by querying the `daily_progress` table and matching `user_id` against the last 7 days of records.
